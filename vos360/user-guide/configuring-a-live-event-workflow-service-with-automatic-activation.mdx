The automatic service activation feature enables users to schedule the activation of a Live Event Workflow service at a specified time.

* When a Live Event Workflow service is created, it remains in the OFFLINE state until activated. To utilize this feature, perform the following:

  * Configure the event’s start time to utilize this feature.

  * Set an end time to automatically stop the service.

  * Optionally, set up a preroll duration.

* The automatic service activation can be enabled globally or at service level.

## Configure automatic service activation

The automatic service activation is only configurable through the **Monitor Event&#x20;**&#x42;asic Settings **APIs**.

## Workflow

1. Enable the Automatic Service Activation (either globally or at service-level), and set up the delay if the default value does not suit your use case.

2. Set up the Global values. \
   Using the `/monitor/v1/live-events/basic-settings` API as indicated above, set the global values as needed.

3. Configure the Service-level workflow.

   1. From the **Configure Channels&#x20;**&#x61;pp:

      * Create a Live event service **without activating it**.

      * It will be in OFFLINE state.

   2. (Optional) From `/monitor/v1/live-events/basic-settings/{id}` API endpoint:

      * If the Automatic Service Activation is not enabled globally, you need to enable it specifically for each service.

      * Using this API, update the **autoOnline** settings:

        * Set **enabled&#x20;**&#x74;o true.

        * If required, update the **delay** field to fit this specific event’s needs.

   3. From the **Monitor Channels&#x20;**&#x61;pp:

      * **Do not bring your service online.**

      * Set &#x61;**&#x20;start time**.

      * Optionally set a preroll duration and an end time.

![image-20251015-131543.png](/images/vos360/b225edfe50c8b44ce4eb1ba2.png)

<Note>
  **Notes**:

  * The Start Time and End Time need to be configured at least 5 minutes in the future.

  * The End time needs to be greater than the start time.

  * If a preroll duration is also set, the preroll start (i.e. start time minus preroll duration) needs to be set at least in 5 minutes in the future.
</Note>

## Response

![image-20251015-132953.png](/images/vos360/29443c1afafb8b42a6f5bcb5.png)

All Live Event settings come with an **autoOnlinelevel** field (in read-only), indicating from where the shown value comes from. The possible values are:

* **DEFAULT**: The shown value is the system’s default value. It is used only when no Global or Service level settings exist.

* **GLOBAL**: The shown value is a global user-defined value, which can be updated with the basic-settings endpoint. It is used whenever no Service-level setting exist for a service.

* **EVENT**: The shown value is a service-specific value, which can be updated with the basic-settings/\{id} endpoint. It is specific to the current service.

## Miscellaneous

<Note>
  **Info**: The expected automatic activation time is processed based on the following:

  * Event’s start time

  * Minus the preroll duration (if defined)

  * Minus automatic activation delay
</Note>

<Note>
  **Note**: This feature only triggers the online action automatically, with the same limitations as a manual online action.

  * The service may not start at the expected time due to lack of resources.

  * If the source is not available, there will be no service output
</Note>

<Note>
  **Notes**:

  * If the expected automatic activation time is already in the past, the service is automatically activated as soon as the start time is set and activation is enabled.

  * If this time is modified in the future (by increasing the start time or decreasing the preroll duration or activation delay) while the service is already online, the service will remain online and will not be set back offline.

  * The activation delay cannot be set to less than 5 minutes to ensure that the service allocation and preparation states are completed before the activation time under nominal conditions (with resources available, etc.).

  * If the activation time is in the past and the user attempts to set the service back offline, this feature will reactivate it. To take the service offline, the activation time must be changed to a future time, or the automatic activation must be disabled (at least for that service).
</Note>
