MK.IO has two live streaming workflows. Use the **Live** interface for new events, sources, and multiview events. Use the Media API workflow when you already automate live events and outputs through the Media API.

## Use Live and multiview

The **Live** interface is the recommended starting point for new work. It keeps source creation, single-source events, multiview events, and playback checks in one workflow. Create sources first, then use them in either a live event or a multiview event.

* [Live and multiview](/mkio/how-to/live-streaming/live) for the complete Live workflow.
* [Create an SRT source](/mkio/how-to/live-streaming/live/create-a-live-source) to prepare Secure Reliable Transport (SRT) ingest.
* [Create a live event](/mkio/how-to/live-streaming/live/create-a-live-event) to stream one source.
* [Create a multiview live event](/mkio/how-to/live-streaming/live/create-a-multiview-live-event) to combine sources in one layout.

## Use the Media API workflow

The established workflow creates Media API live events, live outputs, streaming locators, and streaming endpoints. Keep using it for existing API-backed integrations.

* [Live stream in five minutes](/mkio/getting-started/live-stream-in-five-minutes) for a first Real-Time Messaging Protocol (RTMP) test.
* [Configure a Media API live event](/mkio/how-to/live-streaming/set-up-a-live-streaming-event) for passthrough, encoding, RTMP, encrypted RTMP (RTMPS), SRT, archive, and transcription options.
* [Configure an extended archive window](/mkio/how-to/live-streaming/extended-archive-window) when the default archive duration is not enough.
