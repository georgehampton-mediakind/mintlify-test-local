The MK.IO access model is built in layers. Users belong to an organization, teams group users, roles define capabilities, and scopes define which resources those capabilities apply to. Access is granted by giving a team one or more roles under a scope, then adding users to the team. Granting access team-by-team rather than user-by-user keeps it reusable and easy to audit.

The usual sequence is: identify the users, inspect the available roles and scopes, create or update a team that maps roles to a scope, and add members.

## Invite users to your organization

Invite new users from the **Organization Settings → Users** section, or use the Management API.

```bash
curl -X POST "https://app.mk.io/api/v1/organization/invites" \
  -H "Authorization: Bearer $MKIO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "spec": {
      "email": "jane.smith@example.com",
      "comment": "Video encoding specialist for the Delphi project",
      "teams": ["encoding-team"]
    }
  }'
```

The invited user receives an email with an invitation link. Two things are worth knowing:

- An invitation **expires after 14 days**. Re-send if the window passes.
- An accepted user **automatically joins the Everyone team** in addition to any teams you name in the invite.

## Manage pending invitations

List pending invites and cancel one that is no longer needed:

```bash
# List pending invites
curl -X GET "https://app.mk.io/api/v1/organization/invites" \
  -H "Authorization: Bearer $MKIO_TOKEN"

# Cancel an invite
curl -X DELETE "https://app.mk.io/api/v1/organization/invites/<INVITE_ID>" \
  -H "Authorization: Bearer $MKIO_TOKEN"
```

## Roles and scopes

Before creating a team, inspect the roles and scopes available in your organization. A role record lists its capabilities; a scope record lists the resources it covers.

```bash
curl -X GET "https://app.mk.io/api/v1/organization/roles" \
  -H "Authorization: Bearer $MKIO_TOKEN"

curl -X GET "https://app.mk.io/api/v1/organization/scopes" \
  -H "Authorization: Bearer $MKIO_TOKEN"
```

## Create a team

A team maps users to roles within a scope. Create or replace a team with `PUT`:

```bash
curl -X PUT "https://app.mk.io/api/v1/organization/teams/video-engineering" \
  -H "Authorization: Bearer $MKIO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "spec": {
      "description": "Team for media workflow operations",
      "members": {
        "<USER_ID>": { "isTeamAdmin": true }
      },
      "scopes": {
        "<SCOPE_NAME>": { "roles": ["<ROLE_NAME>"] }
      }
    }
  }'
```

<Warning>
A `PUT` replaces the whole team spec. To change one member or role on an existing team without losing other settings, use JSON Patch instead.
</Warning>

## Update a team with JSON Patch

The team `PATCH` endpoint takes a JSON Patch document (an array of operations), which is the safe way to change one part of a team without resending the whole spec.

**Add a member:**

```bash
curl -X PATCH "https://app.mk.io/api/v1/organization/teams/video-engineering" \
  -H "Authorization: Bearer $MKIO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '[
    { "op": "add", "path": "/spec/members/<USER_ID>", "value": { "isTeamAdmin": false } }
  ]'
```

**Add a role under a scope:**

```bash
curl -X PATCH "https://app.mk.io/api/v1/organization/teams/video-engineering" \
  -H "Authorization: Bearer $MKIO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '[
    { "op": "add", "path": "/spec/scopes/<SCOPE_NAME>/roles/-", "value": "<ROLE_NAME>" }
  ]'
```

**Remove a member:**

```bash
curl -X PATCH "https://app.mk.io/api/v1/organization/teams/video-engineering" \
  -H "Authorization: Bearer $MKIO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '[
    { "op": "remove", "path": "/spec/members/<USER_ID>" }
  ]'
```

Use `replace` on `/spec/members/<USER_ID>/isTeamAdmin` to promote or demote a team member.

## Check what a token can do

To see the capabilities the current token holds, read its role-based access control (RBAC) data. This is the fastest way to debug a `403 Forbidden` response.

```bash
curl -X GET "https://app.mk.io/api/v1/user/rbac" \
  -H "Authorization: Bearer $MKIO_TOKEN"
```

## Accept or decline an invitation (user side)

From the user's perspective, list the organizations they can reach (including pending invites), then accept or decline:

```bash
# List organizations and pending invites
curl -X GET "https://app.mk.io/api/v1/user/organizations" \
  -H "Authorization: Bearer $MKIO_TOKEN"

# Accept an invitation
curl -X PATCH "https://app.mk.io/api/v1/user/organizations/<ORGANIZATION_ID>" \
  -H "Authorization: Bearer $MKIO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "spec": {
      "invite": { "state": "accepted" }
    }
  }'
```

To decline an invite or leave an organization, use `DELETE` on the same resource.

## Common issues

<Accordion title="A PUT wipes team members you meant to keep">
  `PUT` replaces the entire spec. To change one member or role on a live team, use the JSON Patch endpoint.
</Accordion>

<Accordion title="Deleting a team does not remove the users">
  Deleting a team removes the team and the access it granted. The users remain in the organization and can be added to other teams.
</Accordion>

<Accordion title="A restricted token cannot exceed your own access">
  When you design a restricted token, compare it against `/api/v1/user/rbac`. The token's permissions must be a subset of your own. See [API Tokens](/mkio/admin/api-tokens).
</Accordion>
