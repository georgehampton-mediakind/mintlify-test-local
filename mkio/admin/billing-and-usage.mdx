The MK.IO Billing view gives organization administrators a consolidated picture of spending across MK.IO and MK.IO Beam. You can review usage at the organization level, filter by project or payment method, download CSV exports for finance, and manage payment method assignments.

MK.IO bills on metered, pay-as-you-go usage, so these reports map directly to what you are charged.

## Access the Billing view

Go to **Organization Settings → Billing** from the profile dropdown in the top-right corner of the MK.IO portal. The Billing view is available to organization administrators.

## View usage by product

The Billing view groups usage into the following categories:

- **Live Processing and Recording**: Charges for running live events and archiving streams
- **Content Processing and Transcoding**: Job minutes for encoding, AI, and conversion transforms
- **Video Streaming**: Egress and endpoint hours for streaming delivery
- **Content Protection**: DRM and key delivery
- **Storage Management**: Storage for assets and live recordings

Select the current month or a previous month to view usage. Customers with multiple projects can inspect each project individually or view an aggregate summary.

## Filter usage

Use the filters in the Billing view to narrow results:

- **By product**: MK.IO or MK.IO Beam
- **By project**: A single project or all projects
- **By day or month**: Daily or monthly granularity

Beam usage summaries — including encoding and reception hours — are available for customers who access MK.IO directly. Customers accessing through a channel partner see current-month Beam usage on the MK.IO dashboard; full billing details remain managed by the channel partner.

## Download CSV reports

To export usage data for finance or reconciliation, use the Management API reporting endpoint:

```bash
curl -X POST "https://app.mk.io/api/v1/organization/reports/usage" \
  -H "Authorization: Bearer $MKIO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "startDate": "2026-01-01",
    "endDate": "2026-02-01",
    "format": "csv",
    "download": true,
    "filterOnReportedDate": true
  }'
```

Set `filterOnReportedDate` to `true` to align the report with billing dates rather than when usage occurred. This is the correct setting for reconciling against invoices.

The query also supports:

- `granularity`: `hour`, `day`, `week`, `month`, or `year`. Hourly granularity is limited to 31-day ranges.
- `projectNames` or `paymentMethodIds` to filter. These two are mutually exclusive.

For a quick month-to-date view of a single project:

```bash
curl -X GET "https://app.mk.io/api/v1/projects/$MKIO_PROJECT/usage" \
  -H "Authorization: Bearer $MKIO_TOKEN"
```

## Manage payment methods

Each project must be assigned to a payment method. Administrators can view and update payment method assignments from the Billing view.

### View payment methods

```bash
curl -X GET "https://app.mk.io/api/v1/organization/paymentMethods" \
  -H "Authorization: Bearer $MKIO_TOKEN"
```

Read a method's rate card to see per-meter prices:

```bash
curl -X GET "https://app.mk.io/api/v1/organization/paymentMethods/<PAYMENT_METHOD_ID>/rateCard" \
  -H "Authorization: Bearer $MKIO_TOKEN"
```

### Move a project to a different payment method

Organization administrators can move one or more projects to another payment method within the same organization:

```bash
curl -X POST "https://app.mk.io/api/v1/projects/$MKIO_PROJECT/paymentMethod" \
  -H "Authorization: Bearer $MKIO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "paymentMethodId": "<PAYMENT_METHOD_ID>" }'
```

A payment method cannot be removed from a project — only replaced with another. Assigning a new payment method also activates the project if it was inactive.

### Payment method display names

Payment methods support display names to distinguish multiple methods associated with the same sales order. Set a display name through the Management API or the Admin UI.

### Delete a payment method

Organization administrators can delete payment methods from the Admin UI. A deleted payment method no longer appears to the organization's customers, and any redemption links associated with it stop working. A payment method with projects still attached cannot be deleted. A payment method deleted by mistake can be restored via the API.

## Marketplace billing

### AWS Marketplace

MK.IO is available through AWS Marketplace with pay-as-you-go billing. Customers with an AWS enterprise commitment can apply it to MK.IO charges. Consolidated billing appears alongside your existing AWS usage.

MK.IO now supports private offers through AWS Marketplace, including pre-committed agreements with custom rate cards and entitlements.

### Redemption links for multi-organization accounts

Redemption links for direct sales payment methods are scoped to a single organization when possible. If a link cannot be scoped automatically and your account has multiple organizations, MK.IO prompts you to choose which organization to redeem it against.

## Enable operational metrics

Project operational metrics are exported in Prometheus format for integration with external monitoring frameworks. Enabling metrics export is a billable feature.

```bash
curl -X PATCH "https://app.mk.io/api/v1/projects/$MKIO_PROJECT/metricsEndpoint" \
  -H "Authorization: Bearer $MKIO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "spec": { "enabled": true } }'
```

The read response returns `url`, `username`, and `password`. Treat the username and password as secrets. Source values refresh at approximately 30-second intervals.

## Common issues

<Accordion title="A payment method seems stuck on a project">
  A payment method cannot be removed from a project — only replaced with another. Use the reassignment endpoint to move the project to a different method.
</Accordion>

<Accordion title="An hourly report is rejected for too wide a range">
  Hourly granularity is limited to 31 days. Use `day` or coarser granularity for longer date ranges.
</Accordion>

<Accordion title="Report totals do not match an invoice">
  The report defaults to when usage occurred. Set `filterOnReportedDate` to `true` to align with billing dates used on invoices.
</Accordion>
