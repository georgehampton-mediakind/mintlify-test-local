By default, live event recordings become available as assets for VOD playback once the event stops. The archive window controls how much of the live recording the manifest exposes to viewers while the event is running. MK.IO supports archive windows from 1 minute up to 7 days.

## How the archive window works

The archive window is a rolling DVR (Digital Video Recorder) window that determines how far back viewers can seek during a live event. The window advances as new content arrives, so the most recent content is always available.

When the archive window is set to **25 hours or less**, viewers can seek back to the start of the window at any time during the event.

When the archive window is set to **more than 25 hours**, the manifest presents a rolling 25-hour window of the most recent content. Content older than 25 hours is still recorded to storage, but it does not appear in the default manifest response.

After the event stops, the full recording is stored as an asset regardless of the archive window setting.

## Configure the archive window

Set the archive window length when you create your live event. Go to **Live Events → + Create Live Event** and set the **Archive window length** under output settings.

You can specify any duration from 1 minute to 7 days (168 hours). If you are unsure, start with a value that covers your expected broadcast plus some buffer for late viewers.

<Note>
The archive window length is a create-time setting for passthrough events. Plan the duration before you create the event.
</Note>

## Access content older than 25 hours

When the archive window exceeds 25 hours, you can access content outside the default 25-hour manifest window by specifying start and end times as query parameters in the manifest request.

Use the `starttime` and `endtime` query parameters with UTC timestamps in the manifest URL:

```
https://<endpoint>.<region>.streaming.mediakind.com/<locator-id>/<manifest>.ism/manifest(format=m3u8-cmaf)?starttime=2026-05-01T08:00:00Z&endtime=2026-05-01T10:00:00Z
```

This returns only the two-hour segment between 08:00 and 10:00 UTC on May 1, 2026. The timestamps must fall within the archive window duration you configured.

## Use asset filters to control the manifest window

Asset and account filters give you more control over which portion of the archive each manifest request returns. Use a filter when you want to:

- Expose only a specific segment of the live recording to certain viewers
- Create a highlight window from the full archive
- Trim the live edge for delay-sensitive use cases

Create an asset filter with a `presentationTimeRange` to define the window:

```bash
curl -X PUT "https://app.mk.io/api/v1/projects/$MKIO_PROJECT/media/assets/my-live-archive/assetFilters/highlight-window" \
  -H "Authorization: Bearer $MKIO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "properties": {
      "presentationTimeRange": {
        "timescale": 1,
        "startTimestamp": 3600,
        "endTimestamp": 7200
      }
    }
  }'
```

Then reference the filter in the streaming locator's `filters` list, or append it to the manifest URL with the `filter=` parameter. See [Playback Filters](/mkio/delivery/playback-filters) for full details.

## Live-specific filter fields

The `presentationTimeRange` block supports additional fields that only apply to live manifests:

| Field | Description |
| --- | --- |
| `presentationWindowDuration` | The maximum rewind window exposed in the manifest, in timescale units |
| `liveBackoffDuration` | The delay from the live edge, in timescale units |

Use `liveBackoffDuration` when your player needs extra buffer at the live edge to avoid stalls on variable-latency networks.

## Storage and billing

The full archive recording is stored in your connected cloud storage for the entire duration of the event, regardless of the manifest window. Storage charges apply for the full recorded duration. If you do not need the recording after the event ends, delete the output asset to stop ongoing storage charges.

<Warning>
Deleting the output asset removes the full recording permanently. If you plan to use any portion for VOD, create a streaming locator or copy the content to a separate asset before deleting.
</Warning>
