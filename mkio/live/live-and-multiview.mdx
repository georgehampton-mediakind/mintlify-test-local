The Live API in MK.IO extends beyond the per-event model in the Media API by introducing reusable sources, encoding profiles, and scheduling controls. Combined with the Templates API, it lets you define channel configurations once and apply them consistently across many broadcasts. Multiview builds on the same model by composing multiple live sources into a single tiled output stream.

## Live API vs Media API live events

MK.IO offers two live streaming models that serve different use cases.

<CardGroup cols={2}>
  <Card title="Media API Live Events" icon="broadcast-tower">
    Per-event configuration. Each live event is created with its own ingest, encoding, and archive settings. Best for one-off events, simple workflows, and direct RTMP/SRT contribution.
  </Card>
  <Card title="Live API Channels" icon="sliders">
    Template-based, reusable configuration. Define encoding profiles and channel structures once, then run many broadcasts from the same template. Best for recurring shows, 24/7 channels, and multiview.
  </Card>
</CardGroup>

Both models produce HLS and DASH output published through streaming endpoints and locators. The Live API model adds scheduled start and stop controls and the ability to compare template versions side by side.

## Live API resources

The Live API is built around three resource types.

**Sources** define where live video comes from. A source captures the ingest URL, protocol, and any encoding input settings. Sources are reusable across channels, so you can connect the same encoder to multiple shows without reconfiguring it.

**Encoding profiles** define how MK.IO processes the incoming stream. A profile is a versioned, named configuration that specifies codec settings, bitrate ladders, and output formats. The Templates API stores these profiles so you can apply, compare, and update them independently of the channels that use them.

**Channels** tie a source to an encoding profile and define the output. A channel runs continuously or on a schedule. Each channel has a state machine similar to a Media API live event: it starts, runs, and stops. Unlike a live event, a channel's encoding configuration is defined by the profile rather than embedded directly.

## Template-based encoding

The Templates API stores versioned encoding and composition configurations. You can create a new template version, compare it against a previous revision using the side-by-side comparison view in the MK.IO interface, and promote it to production without rebuilding your channels from scratch.

<Tip>
Use template versioning to test encoding changes on a non-production channel before rolling them out. The comparison view highlights metadata and configuration differences between revisions.
</Tip>

## Multiview composition

Multiview combines multiple live sources into one tiled output stream. Viewers see all sources simultaneously, which is useful for monitor walls, sports viewing experiences, and production control rooms.

MK.IO supports two multiview modes:

| Mode | Description |
| --- | --- |
| **Static Multiview** | A fixed tile layout with defined positions for each source. Supports up to 9 tiles. |
| **Elastic Multiview** | Dynamic composition that adapts to the number of active sources. |

Each multiview flow receives its own channel output, published as a standard HLS or DASH stream. A source can be reused up to 250 times in downstream flows across multi-cluster locations using RIST distribution, without distributing multiple copies over the internet.

### Supported inputs for Static Multiview

Static Multiview accepts Teletext tracks at the input and converts them to TTML tracks at the output. It also supports ESAM out-of-band signaling and automation, including slate insertion.

### Tile layouts

Static Multiview layouts support up to 9 tiles per composition. Each tile maps to one source. You configure the tile positions and sizes in the channel template.

## Scheduling

The Live interface provides scheduled start and stop controls for channels. You can set a channel to start at a specific time, run for a defined duration, and stop automatically. This reduces manual intervention for recurring broadcasts.

## Uninterrupted upgrades

Nightly MK.IO control plane upgrades do not interrupt running live events or Live Channel services. Planned service interruptions remain limited to agreed maintenance windows.

## AV1 support

MK.IO live encoding and packaging support the AV1 video codec as an alternative to HEVC, reducing bitrate and CDN costs for internet-delivered streams up to HD resolution.

<Note>
AV1 support is in limited availability and not enabled by default. Contact MK.IO support to enable it for your project.
</Note>
