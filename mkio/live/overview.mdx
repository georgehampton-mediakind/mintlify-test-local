MK.IO provides two live streaming models that you can use together or independently depending on your workflow. Live events, managed through the Media API, handle RTMP and SRT ingest with per-event configuration. Live channels, managed through the Live API, use reusable encoding profiles and templates to run continuous or scheduled broadcasts. Both models produce HLS and DASH output that you publish through streaming endpoints and locators.

## Live events vs Live API channels

MK.IO gives you two paths to get live content to viewers. Choose based on how often you broadcast and how much configuration you want to reuse.

<CardGroup cols={2}>
  <Card title="Live Events (Media API)" icon="broadcast-tower">
    Per-event configuration. Create a live event, connect an encoder, archive the stream to an asset, and publish it through a streaming locator. Best for one-off events and simple workflows.

  <Card title="Live Channels (Live API)" icon="sliders">

## Ingest protocols

Live events accept three ingest protocols:

| Protocol | Description | Supported modes |
| --- | --- | --- |
| **RTMP** | Widely supported by OBS, Wirecast, and hardware encoders | Passthrough and encoding |
| **RTMPS** | Encrypted RTMP for networks that require secure ingest | Passthrough and encoding |
| **SRT** | Secure Reliable Transport — better reliability over unpredictable networks | Encoding only |

<Note>
SRT uses AES-128 encryption by default. Live passthrough events are limited to RTMP and RTMPS ingest.
</Note>

## Event types

When you create a live event you choose between passthrough and encoding mode. This determines what MK.IO does with your incoming stream.

| Mode | What MK.IO does | Best for |
| --- | --- | --- |
| **Live passthrough (up to 5 Mbps)** | Passes the stream through without modification | Low-bandwidth streams encoded at source |
| **Live passthrough (up to 60 Mbps)** | Same as above with a higher bandwidth ceiling | High-bitrate professional sources |
| **Live encoding (720p)** | Produces adaptive bitrate output at 720p and below | Most use cases |
| **Live encoding (1080p)** | Produces adaptive bitrate output up to 1080p | High-quality productions |

Live encoding mode is recommended for most users. MK.IO generates multiple bitrate levels automatically so viewers on different connections all get a smooth experience.

## Archive windows

Every live event records its stream to your connected cloud storage. The archive window controls how much of that recording remains accessible through the manifest during the event.

- Archive windows support durations from **1 minute up to 7 days**.
- When the window exceeds 25 hours, the manifest shows only the most recent 25-hour window for viewers. The full recording is still stored.
- After the event stops, the full recording is available as an asset for VOD playback.

See [Extend the Live Event Archive Window](/mkio/live/extended-archive-window) for configuration details.

## Monitoring

MK.IO provides ingest status and live output state information through the portal and the Media API. You can track whether your encoder is connected, the current state of the live event, and the health of your streaming endpoint. See [Monitor Live Streams and Events](/mkio/live/monitor-live-stream) for details.

## Connection timeout

If MK.IO receives no data on an RTMP or RTMPS connection for 10 seconds, it drops the connection automatically. This timeout is fixed and cannot be configured. Your encoder must reconnect and resume sending to restore the stream.
