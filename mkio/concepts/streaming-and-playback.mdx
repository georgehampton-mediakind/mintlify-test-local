Publishing content for playback in MK.IO requires two infrastructure components: a **streaming locator** and a **streaming endpoint**. Both must be in place before any viewer can watch your content. Understanding how they relate to each other helps you design a delivery architecture that matches your scale and protection requirements.

## Streaming locators

A streaming locator is a resource attached to a specific asset. It defines:

- **Which streaming policy applies** — controlling the protocols, encryption, and DRM settings available for that asset
- **Optional access window** — start and end dates that restrict when content can be played
- **Optional asset filter** — limits or modifies what the manifest exposes without re-encoding

Every asset needs at least one locator before it can be streamed. You can create multiple locators on the same asset — for example, one for free public access and one for DRM-protected subscribers.

### Streaming policies

The streaming policy on a locator determines which protocols and protections are available. MK.IO includes several predefined policies:

| Policy | Use when |
| --- | --- |
| `Predefined_ClearStreamingOnly` | Adaptive streaming (HLS/DASH) with no DRM or download |
| `Predefined_DownloadAndClearStreaming` | Both streaming and direct file download, no DRM |
| `Predefined_MultiDrmCencStreaming` | HLS/DASH protected with Widevine and PlayReady |
| `Predefined_MultiDrmStreaming` | HLS/DASH protected with Widevine, PlayReady, and FairPlay |

For DRM-protected policies, you must also attach a **content key policy** to the locator. See [Content Protection](/mkio/concepts/content-protection).

### Locator names and paths

The locator name you choose appears in the playback URL path. Keep locator names URL-safe (lowercase letters, numbers, and hyphens). Locator names must be unique within a project.

## Streaming endpoints

A streaming endpoint is the delivery server that handles viewer requests. It reads content from your connected storage, packages it dynamically as HLS or DASH, and serves it to media players. Each endpoint has a hostname that becomes part of every playback URL for assets assigned to it.

### Endpoint types

| Type | Capacity | Best for |
| --- | --- | --- |
| **Shared** | Up to 600 Mbps on shared infrastructure | Development, testing, and workloads within the shared capacity ceiling |
| **Dedicated** | 200 Mbps of guaranteed bandwidth per unit | Production workloads requiring dedicated, scalable capacity |
| **CDN** | Backed by dedicated capacity with integrated edge caching | Production delivery that benefits from a CDN in front of your origin |

You can scale dedicated endpoints by adding units. A single dedicated unit provides 200 Mbps; add more units to increase capacity proportionally.

<Warning>A running streaming endpoint incurs costs even when no content is being played. Stop endpoints you are not using to avoid unnecessary charges.</Warning>

### Endpoint and locator separation

You create one endpoint per environment (for example, `production` and `staging`) and reuse it across many assets. A locator belongs to one asset, but any running endpoint in the same project can serve its content. When you want to publish an asset, you pair a locator with an endpoint on the asset page to generate the playback URLs.

## Playback URL format

When you pair a locator with an endpoint, MK.IO generates HLS and DASH URLs in this format:

```
https://<endpoint-name>.<region>.streaming.mediakind.com/<locator-id>/<manifest>.ism/manifest(format=m3u8-cmaf)
https://<endpoint-name>.<region>.streaming.mediakind.com/<locator-id>/<manifest>.ism/manifest(format=mpd-time-cmaf)
```

For DRM-protected content, the same URL paths apply. The player requests a license from the DRM license server using the key server URL embedded in the manifest.

## Publish content step by step

To publish an asset for playback:

1. Create a running streaming endpoint (or use an existing one).
2. Create a streaming locator on the asset, choosing the appropriate streaming policy.
3. On the asset page, select the endpoint and locator and click **Apply**.
4. Copy the generated HLS or DASH URL.

For a full walkthrough, see [Publish Content for Streaming](/mkio/delivery/stream-content).
