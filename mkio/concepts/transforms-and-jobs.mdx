VOD processing in MK.IO uses two resource types that work together: a **transform** defines what processing to perform, and a **job** runs that transform against a specific input. Separating the definition from the execution means you configure a processing recipe once and reuse it across as many files as you need.

## Transforms

A transform is a reusable processing definition that describes one or more outputs to produce. Each output in a transform has a **preset** — a configuration that tells MK.IO exactly what to generate.

Common preset types include:

| Preset type | What it produces |
| --- | --- |
| **Adaptive bitrate encode** | Multiple video renditions at different bitrates for smooth HLS or DASH playback |
| **Thumbnail** | Still image frames extracted from the video at regular intervals or specific timecodes |
| **AI transcription** | WebVTT or TTML subtitle files generated from the audio track |
| **AI dubbing** | Translated audio tracks for multi-language VOD |
| **Format conversion** | Re-wrapped or re-encoded files in a different container or codec |

A single transform can define multiple outputs — for example, an ABR encode and a set of thumbnails in one pass. MK.IO processes all outputs in a single job.

MK.IO provides built-in transform presets (such as `AdaptiveStreaming` for standard ABR output) and lets you create custom transforms with fine-grained encoder settings.

## Jobs

A job is a single execution of a transform against a specific input. When you create a job, you specify:

- **Which transform to use**
- **The input** — an existing asset in your project, or an external HTTPS/SAS URL
- **The output** — a new asset name and the storage account where the output files will be written

### Job states

Jobs move through a predictable state sequence:

```
queued → scheduled → processing → finished
```

If processing fails, the job enters an **error** state with a description of what went wrong. Jobs that are no longer needed can be cancelled while queued or scheduled, and deleted after they finish.

### Job priority

When you create a job you can set its priority:

| Priority | Behavior |
| --- | --- |
| **Low** | Background processing that yields to other jobs |
| **Normal** | Default. Processed in the order jobs are received |
| **High** | Picked up next when a processing slot is free; does not interrupt running jobs |

Use High priority for time-sensitive encodes and Low priority for batch jobs that run overnight.

### Monitoring jobs

Track job progress from the **Video Processing** page in the portal. The progress percentage updates as each output rendition is produced. You can also poll the jobs endpoint in the Media API for programmatic monitoring.

Once a job reaches **finished**, the output asset appears on the **Assets** page. You can then attach a streaming locator to publish the content.

## Inputs and outputs

**Input types:**

- **Asset** — select an existing asset in your project by name. The job reads files from the asset's storage container.
- **External URL** — provide a full HTTPS or SAS URL to a publicly accessible file. MK.IO fetches the file at job start.

**Output:**

Every job writes its results to an output asset. You specify the asset name and the storage account at job creation time. MK.IO creates the output asset container automatically.

<Tip>Use descriptive output asset names that include the source name and transform type — for example, `interview-2024-abr` or `promo-thumbnails` — to make assets easy to find after processing.</Tip>

## Reusing and duplicating jobs

The portal lets you duplicate an existing job from the Jobs list to reuse its settings with minor adjustments. This is useful when you regularly process files with the same transform and just need to change the input or output asset name.
