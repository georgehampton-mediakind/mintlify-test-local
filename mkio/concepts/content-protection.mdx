MK.IO provides built-in DRM support for protecting live and VOD content. Protection is applied through a combination of **content key policies** and **streaming policies** on your streaming locators. Understanding how these two resources interact lets you configure the right level of protection for every piece of content.

## How content protection works

When a viewer requests protected content, the following happens:

1. The media player detects DRM signaling in the HLS or DASH manifest.
2. The player sends a license request to the MK.IO DRM license server, including any token the player has acquired.
3. MK.IO evaluates the **content key policy** attached to the streaming locator.
4. If the request satisfies the policy requirements, MK.IO returns a license containing the decryption key.
5. The player decrypts and plays the content.

This flow means viewers never receive the raw decryption key — they receive a time-limited license that the DRM system in their device or browser manages.

## Supported DRM systems

MK.IO supports the three major DRM systems used in commercial video distribution:

| DRM system | Platforms | Encryption standard |
| --- | --- | --- |
| **Widevine** | Android, Chrome, Firefox, Edge, most Smart TVs | CENC (Common Encryption) |
| **PlayReady** | Windows, Xbox, Edge, select Smart TVs | CENC |
| **FairPlay** | Apple devices (iOS, macOS, tvOS, Safari) | HLS encryption (CBCS) |

To support the broadest audience, use a multi-DRM streaming policy such as `Predefined_MultiDrmStreaming`, which combines all three systems. MK.IO serves the appropriate license based on the DRM system the player requests.

## Content key policies

A **content key policy** defines the rules MK.IO uses to issue content keys. You can require:

- **Open (no token)** — any request receives a license. Use this for preview content or internal testing.
- **Token-based authorization** — the player must present a valid JSON Web Token (JWT) or Simple Web Token (SWT) to receive a license. Use this for authenticated playback.

Token-based authorization lets you bind license issuance to your own authentication system. You define the token requirements in the content key policy, and your backend issues signed tokens to authenticated viewers.

### Content key policy configuration

When you create a content key policy, you configure one or more **policy options**. Each option defines:

- **DRM type** (Widevine, PlayReady, or FairPlay)
- **License type** (persistent or non-persistent)
- **License duration** — how long the issued license is valid
- **Token requirements** — the issuer, audience, and required claims if using token-based authorization

A single content key policy can contain options for multiple DRM systems so that one policy covers all platforms.

## Streaming policies with DRM

Attach DRM protection to a streaming locator by selecting a DRM streaming policy and providing a content key policy:

| Streaming policy | DRM systems covered |
| --- | --- |
| `Predefined_MultiDrmCencStreaming` | Widevine and PlayReady (CENC) |
| `Predefined_MultiDrmStreaming` | Widevine, PlayReady, and FairPlay |

When you create a streaming locator with a DRM policy, you must also specify the content key policy that defines the license rules. MK.IO links the two resources so the license server knows which rules to apply when a player requests a key.

## Apply content protection

To protect a piece of content:

<Steps>
  <Step title="Create a content key policy">
    Go to **Content Key Policies** in the MK.IO portal and click **+ Create Policy**. Configure the DRM options, license duration, and token requirements for your use case.
  </Step>
  <Step title="Create a DRM streaming locator">
    On your asset, add a streaming locator and select a DRM streaming policy (for example, `Predefined_MultiDrmStreaming`). In the **Content key policy** field, select the policy you created.
  </Step>
  <Step title="Publish with an endpoint">
    Pair the locator with a running streaming endpoint to generate the protected HLS and DASH URLs.
  </Step>
  <Step title="Issue tokens to viewers">
    If your content key policy requires token-based authorization, your backend must issue signed JWTs or SWTs to authenticated viewers. The player presents the token in the license request.
  </Step>
</Steps>

## Live vs VOD protection

Content protection works the same way for live and VOD content. For live streams, attach the DRM locator to the live output asset before starting the event so protected playback is available as soon as the stream begins.

<Tip>Test your DRM configuration with open (no-token) authorization first to confirm the DRM handshake works, then add token requirements once playback is verified.</Tip>
