MediaKind exposes a set of REST APIs that cover every layer of the platform — from media processing and live streaming to device fleet management and organization administration. All cloud APIs share a common base URL and bearer token authentication model, while the Beam Channels API is served directly from the edge device. Download OpenAPI specs from the individual API pages to generate clients or explore endpoints in your tooling of choice.

## Base URL and Authentication

All MK.IO cloud APIs use the base URL `https://app.mk.io`. Every request requires a bearer token in the `Authorization` header:

```http
Authorization: Bearer <your_token>
```

Create and manage your tokens in your [profile settings](https://app.mk.io/user/profile) under **Your personal API tokens**. See the [API tokens guide](/mkio/admin/api-tokens) for full instructions.

<Note>
  OpenAPI specification files are available for download from each individual API reference page. Use them to generate SDKs, import into Postman, or explore schemas in any OpenAPI-compatible tool.
</Note>

## How the APIs Fit Together

The APIs are separate services, but most platform workflows combine more than one. A typical integration follows this sequence:

<Steps>
  <Step title="Provision with the Management API">
    Create a project, assign billing, and issue tokens for your automation before calling any other API.
  </Step>
  <Step title="Configure infrastructure (Beam only)">
    Use the **Infrastructure API** to define the sites and networks where your Beam devices will operate.
  </Step>
  <Step title="Process and publish content">
    Use the **Media API** for VOD workflows, and the **Live API** with **Templates API** for live encoding and multiview.
  </Step>
  <Step title="Operate your Beam fleet">
    Use the **Fleets API** to onboard devices, manage backups, and push software updates.
  </Step>
  <Step title="React to events">
    Return to the **Management API** to register webhook rules so your integration responds to state changes rather than polling.
  </Step>
</Steps>

<Tip>
  Not sure which API owns your workflow? See [Which API to Use](/api-guides/getting-started/which-api) for a decision table and common workflow combinations.
</Tip>
