A live encoder compresses uncompressed baseband video and audio into a lower-bitrate encoded format suitable for contribution, broadcast distribution, or streaming. MK.IO Beam's Live Encoding converts live video feeds into streams for internet, IP, and broadcast delivery. You configure encoding settings, output profiles, and delivery targets through the MK.IO Beam interface, without managing the underlying processing pipeline directly.

## Processing Stages

The Live Encoder processes content through the following functional stages in sequence:

**Input** — the encoder receives and ingests the video signal. Supported input types include SDI for HD and UHD workflows and IP transport streams.

**Decoding** — the input can optionally be decoded using a range of audio and video codecs before further processing.

**Pre-processing** — after decoding, a range of pre-processing functions can be applied to improve signal quality or adapt the video before encoding.

**Video and audio encoding** — the video and audio are encoded. Audio pass-through is also supported, meaning audio can be forwarded without re-encoding.

**Media composing** — a specific input mode for content operations. You can schedule, start, and stop blackout, logo insertion, crawler insertion, switching to an alternate live input, or switching to a TS playlist.

**Post-processing** — after encoding, additional post-processing features are available, including SCTE-35 and SCTE-104 signalling for content replacement and advertising.

**Output** — the encoder produces an MPEG-2 Transport Stream over IP, in either CBR or adaptive bitrate modes. FEC (Forward Error Correction) and redundant IP outputs are also supported.

## Rate Control and Statistical Multiplexing

MK.IO Beam's Live Encoder uses a leaky bucket rate control model, which defines the constraints on bitrate variation that a decoder can handle. See [Leaky bucket concept](https://docs.mediakind.com/beam/live-encoder/leaky-bucket) for an explanation.

For headend workflows, Live Encoder services can participate in statistical multiplexing (statmux) as slave services under a Multiplexer master. The Multiplexer dynamically adjusts each encoder's bitrate allocation based on scene complexity across the pool, improving overall quality within a fixed output bandwidth. See [Advanced rate control](https://docs.mediakind.com/beam/live-encoder/rate-control) for details.

## Common Use Cases

- **Contribution encoding** — compress live video for transport from a field location to a production facility.
- **Headend encoding** — produce compressed channels for multiplexing and distribution over cable, IPTV, or satellite.
- **OTT encoding** — produce streams for adaptive bitrate packaging and delivery.

## Configure the Live Encoder Service

The following sections explain the basic configuration for the Live Encoder component. For advanced configuration, see:

- [Input parameters](https://docs.mediakind.com/beam/live-encoder/configure/input)
- [Encoding parameters](https://docs.mediakind.com/beam/live-encoder/configure/encoding)
- [Output parameters](https://docs.mediakind.com/beam/live-encoder/configure/output/configure-output)

<Steps>
  <Step title="Open the Live Encoder Settings">
    From the **Home** page, click the edit icon next to the **Live Encoder** component within the feed. The Live Encoder settings open.

    On the **General** tab, the name is already pre-defined. It will be incremented at each new feed instance, so you do not need to change it.
  </Step>

  <Step title="Configure the Input">
    Go to the **Input** tab. In the **General parameters** section, select the input type — either [**SDI**](#sdi-input) or [**SMPTE ST 2110**](#smpte-st-2110-input).
  </Step>
</Steps>

### SDI Input

Before you start, ensure you have already [set up the SDI card for HD or UHD operation](https://docs.mediakind.com/beam/system-admin/maintenance/setup-sdi-asi-card).

<Steps>
  <Step title="Set the Input Type">
    From the **General parameters** section:
    - Set the input **Type** to **SDI**.
    - Select a **Connector** from the drop-down list.
    - You can keep the SDI card number (default **1**) or change it.
  </Step>

  <Step title="Configure Input Streams">
    Go to the **Input streams selection** section. The input video is already configured, but you can add an input audio:
    1. Go to the **Audio ID** section.
    2. Click **Add**. Keep the default parameters or modify them as needed.
    3. Click **OK** to validate.
  </Step>

  <Step title="Save">
    Click **Save and continue** to save your changes.
  </Step>
</Steps>

### SMPTE ST 2110 Input

Before you start, ensure you have already [set up the SMPTE ST 2110 input](/beam/contribution/smpte-2110).

<Steps>
  <Step title="Set the Input Type">
    In the **Input** > **General parameters** section, set the input **Type** to **SMPTE ST 2110**.
  </Step>

  <Step title="Configure the Input Video Stream">
    In the **Input streams selection** section, go to the **Video ID** section. Click the edit icon, then enter the **SDP file location**. Click **OK** to validate.
  </Step>

  <Step title="Add and Configure the Input Audio Stream">
    In the **Input streams selection** section, go to the **Audio ID** section. Click **Add**, then enter the **SDP file location**. Click **OK** to validate.
  </Step>

  <Step title="Save">
    Click **Save and continue** to save your changes.
  </Step>
</Steps>

<Note>
  See also: [Limitations and Considerations for ST2110 and PTP](/beam/contribution/smpte-2110#limitations-and-considerations-for-st2110-and-ptp), [Configure SDP files on MK.IO Beam](/beam/contribution/smpte-2110#configure-sdp-files-on-mkio-beam), and [Setup the PTP for ST 2110](/beam/contribution/smpte-2110#configure-ptp-for-st-2110).
</Note>

## Configure Video, Audio, and Data Components

### Configure the Video Component

1. Go to the **Video encoding** section.
2. Click the edit icon to check and configure the video parameters.
3. Select the appropriate parameters for the video encoding.
4. Click **OK** to validate.

### Configure the Audio Component

1. Go to the **Audio encoding** section.
2. Click **Add**. A new window is displayed. By default the audio codec is set to **Pass-through**, but you can change it.
3. Select the appropriate parameters for the audio encoding.
4. Click **OK** to validate.

Click **Save and continue** to save your changes.

## Configure the Output

<Steps>
  <Step title="Open the Output Tab">
    Go to the **Output** tab. A default output has already been created.
  </Step>

  <Step title="Edit Output Parameters">
    In the top-right corner, click the edit icon.

    Scroll to the **Common MPEG-2 TS parameters** section. You can change parameters such as **Standard**, **PCR PID**, **Program number**, **Service name**, and **Service provider**.
  </Step>

  <Step title="Configure Output Streams">
    Scroll to the **Output streams** section. Click the edit icon, then tick the audio stream. Change PIDs if needed.

    Click **OK** to validate.
  </Step>

  <Step title="Save">
    Click **Save and continue** to save your changes.
  </Step>
</Steps>

## Configure Advanced Parameters

### CBR Output

To ensure that the video is output as a CBR elementary stream:

1. Go to the **Advanced parameters** tab.
2. Click **Add**, then set `Mpeg2ts.NullPacketStuffing` to `False`.
3. Click **Save and exit** to finalize the service configuration.
4. Select **Home** from the left menu bar to return to the Home page.

### SCTE-35 Pass-Through

If passing through SCTE-35 messages with a default configuration, a high proportion of null splice messages will be output compared to splice messages containing actual splices. To reduce null splice messages, use the `capDmif.maxScte35Bitrate` advanced parameter.

Setting `capDmif.maxScte35Bitrate` to `7520` reduces the number of null splice messages in the output.
