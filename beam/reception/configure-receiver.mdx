A broadcast receiver demodulates an incoming signal and decodes the video and audio it contains, converting a compressed transport stream back into a baseband output. Receivers are a fundamental part of any workflow where content arrives over satellite or IP and needs to be decoded for monitoring, processing, or re-distribution.

MK.IO Beam's Receiver handles both satellite and IP inputs. For satellite, it supports DVB-S, DVB-S2, and DVB-S2X standards with hardware demodulator cards. For IP, it accepts transport stream inputs directly from the network. You can route a single satellite input to multiple Receiver services, or assign each input independently.

## Feed Components in a Reception Workflow

After a feed has been created, configure each service within the feed individually:

- [**Receiver service**](#receiver-configuration-type) — required. Handles input, decryption, decoding, and output.
- [**Multiplexer service**](https://docs.mediakind.com/beam/multiplexer) — optional. Combines or re-multiplexes transport streams.
- [**Live Encoder service**](https://docs.mediakind.com/beam/live-encoder/configure) — optional. Re-encodes decoded content for distribution.

The Reliable Transport service is not included in all MK.IO Beam feed templates. It can be added separately via the **Services** page. See [Reliable Transport Configuration](https://docs.mediakind.com/beam/reception/configure-feed-components/reliable-transport).

<Warning>
  When editing service parameters, do not modify any interfaces configured to use the `tap0` or `lo` interfaces. These are used internally to pass data between services.
</Warning>

## Decoding

Once the transport stream is received, MK.IO Beam decodes the video and audio from the selected service. By default, the first video and audio components listed in the service Programme Map Table (PMT) are decoded automatically. Supported audio formats include MPEG-1 Layer II, Dolby Digital, and Dolby Digital Plus, as well as pass-through of formats such as Dolby E and LPCM.

See [Video Decoding](/beam/reception/tech-specs#video-decoding) and [Audio Decoding](/beam/reception/tech-specs#audio-decoding) in the technical specifications for a full list of supported formats. See [Decoding configuration](https://docs.mediakind.com/beam/receiver/decoding) for detailed configuration steps.

## Outputs

MK.IO Beam's Receiver delivers decoded output in several formats:

- **SDI** (HD, 3G SDI) — for broadcast equipment and monitors.
- **UHD SDI** — for ultra-high-definition workflows.
- **SMPTE ST 2022-6** — for SDI over IP in production environments.
- **SMPTE ST 2110** — for uncompressed IP video and audio in IP studio environments.
- **HDR to SDR conversion** and HD downconversion — for compatibility with legacy equipment.
- **SCTE-35 to SCTE-104 conversion** — for passing ad insertion signals to downstream encoders.

Multiple outputs can be configured from a single Receiver service. See [Output configuration](https://docs.mediakind.com/beam/receiver/output) for the full range of options.

## Decryption

Broadcast streams are often encrypted to prevent unauthorized access. MK.IO Beam's Receiver supports several decryption methods:

- **BISS (Basic Interoperable Scrambling System)** — a broadcast standard for contribution and distribution encryption (BISS1, BISS2, BISS-CA).
- **Director 6** — MediaKind's conditional access system with over-air-control functionality.
- **DVB-CI** — a common interface standard using a removable Conditional Access Module (CAM).

See [Decryption configuration](/beam/reception/decryption) for setup details.

## Receiver Configuration Type

When a Receiver service is created by [adding a Feed](https://docs.mediakind.com/beam/web-interface/#add-a-feed), one or more services are generated from a template and the **Configuration Type** is selected automatically based on the chosen feed type.

When [creating a service](https://docs.mediakind.com/beam/web-interface/services/#create-a-service) directly, you are prompted to select the **Configuration Type** for a Receiver service.

The Configuration Type determines the behaviour of the Receiver service:

| Configuration Type | Description |
| :-- | :-- |
| **TS passthrough** | Does not decode video, audio, or data, but supports descrambling. The input transport stream is output as an IP/UDP multicast. |
| **SD/HD** | Decodes video (SD and HD), audio, and data, and supports descrambling. Output formats include SDI. |
| **UHD** | Decodes video (SD, HD, and UHD), audio, and data, and supports descrambling, with output formats such as SDI. Includes additional UHD-specific configuration settings. |

If the selected Configuration Type is not appropriate, some configuration settings may be unavailable in the web interface, or the Receiver service may be prevented from starting.

<Note>
  If the service is blocked from starting, an alarm is raised indicating that the service configuration is incompatible with the selected Configuration Type. Refer to the alarm description for guidance on resolving the issue.
</Note>

### Change the Configuration Type

To change the configuration type for an existing Receiver service:

<Steps>
  <Step title="Open the Receiver Edit Page">
    From the **Home** page, select the RECEIVER item from the required feed, then click the edit icon.
  </Step>
  <Step title="Select the Configuration Type">
    Select the appropriate type from the **Configuration Type** drop-down list.
  </Step>
  <Step title="Save">
    Click **Save and Continue** to apply the change.
  </Step>
</Steps>
